## Defects found and corrected

- `SELECT FOR UPDATE` applied the organization update policy and hid organizations from MEMBER/VIEWER. Organization advisory transaction locks now serialize changes, followed by a fresh membership check. Invitation acceptance takes the same lock.
- A same-document invitation hash did not trigger the mounted UI; added hashchange handling.
- Browser assertions matched Next's route announcer as well as the business alert; scoped the locator to main. Logout acceptance now waits for the asynchronous operation to finish before checking session revocation.
- Legacy pnpm deploy re-resolved the entire workspace and exhausted build memory. Enabled injected workspace dependencies, synchronized build outputs and used dedicated production deploy. A 512 MB local packaging check produced 112 production packages and imported the generated tenant Prisma client; final Linux container CI and actual deployment passed.
- API startup now refuses incomplete/missing forced tenant policies as well as privileged database roles.
- Windows Prisma DLL generation must precede live API/test processes. A local non-escalated test rerun was denied its loopback connection by the sandbox; the authorized network rerun passed all 36 tests. Failed attempts are not counted as passes.

## Limits / unexecuted work

- NOT_RUN: sustained production load/capacity tests, multi-host failover and off-host disaster recovery. This is a single-host deployment, not an HA/SLA claim.
- NOT_RUN: manual login as each real legacy customer. Digest reconciliation and the migration fixture verify preservation; public acceptance uses controlled accounts.
- Out of scope: SSO/MFA, password reset, payments, CRM and automatic invitation email delivery. Account email ownership is not externally verified; an invitation is bound to the matching local account email plus its private single-use token, not a verified corporate identity.
- Current UI lists the latest 100 audit events/projects and up to 200 tasks per project; full pagination and audit export are not implemented. Roles apply within the organization, not separately to each project. A database administrator can perform explicit maintenance; audit immutability protects application operations, not a hostile DBA.
- BLOCKED release gates: none. Known unresolved functional FAILs in the accepted scope: none. Historical engineering/performance documents are not new SaaS performance evidence.
